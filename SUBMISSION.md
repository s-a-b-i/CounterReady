# SmallPrint: Devpost submission

## Text description

**Tagline:** Looks right. But should I buy it?

**Inspiration.** A product photo tells you if an earring is beautiful. It can't tell you if it's right for you. Photos are cropped to fill the frame, so a 1 cm stud and a 9 cm chandelier look the same size, and shoppers only learn the truth, the weight, the drop, the "final sale" clause, when the parcel arrives.

**What it does.** SmallPrint is an earring-shopping decision assistant. A shopper sets a brief (budget, longest drop, fastening, material, occasion), uploads a side-profile selfie, and tries on up to three earrings with the **YouCam Earring VTO API**. Each AI preview sits next to the real catalogue facts (to-scale drop ruler, weight against everyday objects, fastening, material, price, return window, final-sale flag), with the winning cell per row highlighted *against the shopper's own brief*. The shopper marks each piece Buy / Maybe / Skip with a reason, and gets a shareable decision card (PNG, print, public link).

**eCommerce value.** Virtual try-on answers "does it look good". SmallPrint answers the question that actually drives returns: "is it the right size, weight and risk for me". For a retailer this means fewer size-surprise returns, higher purchase confidence, and a shareable artefact (the card) that carries the shopper's decision to friends. The catalogue-driven design means any store's product data can feed it.

**How we use YouCam.** Per product: `POST /s2s/v2.0/file` (signed upload of selfie + single-earring reference), `POST /s2s/v2.0/task/2d-vto/earring` with the declared `earring_scale` in centimetres and the ear side, then polling `GET /s2s/v2.0/task/2d-vto/earring/{task_id}`. Results are downloaded, compressed and stored (the provider URL is short-lived), then served from our own endpoint.

**Honesty by design.** Every image is labelled (AI preview, pre-generated example, catalogue photo). Every fact carries its source: generated by YouCam, from the seller's catalogue, or computed by SmallPrint. "Fit to your brief" is a plain met/partial/miss checklist, not an invented score. We never claim allergy safety, and the selfie is never stored.

**How we built it.** Next.js 16 (App Router, strict TypeScript), Tailwind v4, Framer Motion, Zod; Neon Postgres via the serverless driver and Drizzle (catalogue, anonymous sessions, try-ons, stored previews, decisions, a usage ledger). A transaction-guarded budget (advisory lock on the ledger), an input-hash cache, refunds for never-created tasks, rate limits, magic-byte image sniffing, a delete-my-data endpoint, Vitest unit tests and a Playwright happy-path test.

**Challenges.** The docs page for the Earring API doesn't show request bodies, so the task payload (`source_info` / `object_infos[].parameter`) was verified against the published OpenAPI spec and the live API. Keeping a shared demo key alive for judges until 20 Nov drove the DB-enforced budget, cache and graceful "credit limit" state.

**What's next.** Real product photography and a retailer feed importer; stacked (multi-ear) try-ons; a merchant dashboard showing which specs make shoppers skip.

**Built with:** YouCam Earring VTO API, Next.js, React, TypeScript, Tailwind CSS, Framer Motion, Neon Postgres, Drizzle ORM, Zod, sharp, Vercel.

## What was built during the submission period

Everything in this repository was created during the hackathon submission period: the Next.js app and design system, the Neon schema and seed, the YouCam client and response adapter, the budget guard, cache and API routes, the full six-step flow, decision card export/sharing, privacy tooling, tests, and docs. The only third-party content is the Pexels sample portrait (licence noted in the README), fonts via `next/font`, and open-source libraries.
